# Bộ cài gọn 1.0.2

Người dùng yêu cầu hợp nhất bản `tan` cũ lên `master` trước, rồi triển khai thu gọn trên `tan`. `master` đã được đẩy lên commit `8fe4016` trước khi thay đổi đóng gói.

## Cấu trúc sau cài

```text
RHM/
  RangHamMat.Wpf.exe
  appsettings.json
  Dicom.Native.dll
  AI/           cấu hình và prompt
  Database/     QLBenhVienRangHamMat.sql
  DuLieu/       ảnh X-quang và nguồn/giấy phép
  KioskServer/  executable API, cấu hình và wwwroot
```

WPF và API có bundle self-contained riêng. Thư viện ngôn ngữ, runtime .NET và các DLL thông thường nằm trong executable; không trimming. .NET tự giải nén các thư viện native được bundle vào cache `%TEMP%/.net` khi cần. Riêng `Dicom.Native.dll` là mixed-mode C++/CLI, cần file thật cho các export native nên giữ một bản cạnh mỗi executable. Bộ kiểm đã bắt được bốn lỗi giải mã DICOM nén khi thử gom cả DLL này. Đây là giảm số file tại thư mục cài đặt; runtime và chức năng vẫn đầy đủ. [Tài liệu single-file của Microsoft](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview).

Giữ nguyên nội dung/đường dẫn SQL, cấu hình, prompt, ảnh và trang Kiosk. Không đóng gói khóa AI cục bộ hay PDB/tài liệu API của thư viện WebView2. API ưu tiên executable; bản phát triển DLL vẫn có fallback dotnet. Các lần publish dạng thư mục/single-file dùng thư mục trung gian riêng để tránh lẫn DLL cũ.

## Build và chuyển máy

1. Visual Studio 2022: chọn **Release**, **Rebuild** project **RHM**.
2. Lấy `RHM/Release/setup.exe` và `RHM/Release/RHM.msi`, giữ hai tệp cạnh nhau, chạy setup.exe.
3. Lần mở đầu chọn SQL Server/database như trước. Database nghiệp vụ nằm trong SQL Server; file trong thư mục Database là script khởi tạo/đồng bộ. Máy trạm vẫn cần quyền truy cập SQL, WebView2 Runtime cho trang AI và Visual C++ Redistributable theo yêu cầu native codec hiện có.

Publish không dùng MSI:

```powershell
dotnet publish RangHamMat.Wpf -c Release -p:PublishProfile=FolderProfile -o PhatHanh
powershell -NoProfile -ExecutionPolicy Bypass -File tools/KiemTraBanPhatHanhGon.ps1 -ApplicationFolder PhatHanh
```

Profile MSI xuất vào `RangHamMat.Wpf/bin/Release/net8.0-windows/win-x64/publish-msi-compact`; FolderProfile mặc định dùng `publish-compact` cùng cấp. Khi tự chọn `-o`, dùng một thư mục phát hành mới để không giữ lẫn tệp do thao tác sao chép thủ công trước đó.

Version WPF/API/MSI là 1.0.2, MSI đổi ProductCode/PackageCode và giữ UpgradeCode. Cờ yêu cầu cấu hình SQL sau cài mới vẫn được quản lý bởi MSI. Không thay database hay profile SQL đã mã hóa.

## Kiểm chứng

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/KiemTraCauHinhSauCaiDat.ps1 -PublishPath RangHamMat.Wpf/bin/Release/net8.0-windows/win-x64/publish-msi-compact
powershell -NoProfile -ExecutionPolicy Bypass -File tools/KiemTraBanPhatHanhGon.ps1 -ApplicationFolder RangHamMat.Wpf/bin/Release/net8.0-windows/win-x64/publish-msi-compact
powershell -NoProfile -ExecutionPolicy Bypass -File tools/KiemTraDicomXquang.ps1 -BanGon
```

Bộ kiểm thứ nhất chỉ đọc MSI, đối chiếu toàn bộ đường dẫn/kích thước với publish và cờ SQL; bộ kiểm thứ hai so SHA256 tài nguyên với mã nguồn, kiểm số file và chỉ cho phép DLL codec DICOM nằm ngoài bundle. Bộ kiểm DICOM có tùy chọn publish single-file rồi chạy chuyển đổi tổng hợp và viewer WPF. Kiểm runtime dùng `Test/InstallerRuntimeChecks` publish single-file self-contained, đặt riêng executable helper cạnh `KioskServer` của payload MSI; không chép DLL/runtime phụ vào payload.
